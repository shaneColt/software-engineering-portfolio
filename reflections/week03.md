Handout B: Team Process Description — QuickBuild Solutions
Task 2:
the first weakness is that requirements are only communicated verbally and developers rely on the team leads memory. this is mainly an absense of process, rather than a problem of that a lightweight agile process would accept. A simple improvment would be to write each requirement as a short user story with clear acceptance critera and store them in a shared document or board.
The second weakness is that developers push code directly to the main branch without another developer reviewing it. a lightweight agile process would normally catch this through practices such as code reviews and version control. A low cost improvement would be to require another developer to review change before it is merged to the main branch
The third weakness is that testing is only done once by the developer who wrote the feature. A simple improvement would be to create a small checklist of acceptance tests for each feature and have another team member test it before release. This would be a should as it would catch errors that the original developer may have missed
